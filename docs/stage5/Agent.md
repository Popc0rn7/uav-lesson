# Stage 5：Qwen—Jev 自主任务与灯箱

Stage 5 把自然语言任务接到仿真无人机：Qwen 拆分阶段并验收，Jev 决定当前阶段的行为，确定性执行器检查约束并通过 PX4 MAVLink Offboard 控制无人机。灯箱展示计划、感知、模型活动、执行状态与用量。

当前是 **PC 仿真 demo**。Qwen 服务可以运行在 RoboPi，但飞行执行器、DINO client、任务运行器和灯箱仍在 PC；不是把自主飞行程序部署到了 PX4 或 RoboPi。操作与准备统一见 [Hands-on](Hands-on.md)，逐次实测和失败证据见 [Validation](Validation.md)。

## 1. 当前能力与验证结果

仅支持两个阶段技能：

| 技能 | 行为 | 明确不提供的能力 |
| --- | --- | --- |
| `observe_target` | 原地观察并确认红色车辆/方块 | 主动转头、移动搜索、换观察点 |
| `follow_red_vehicle` | 目标车后上方跟随，距离3～12m、上方1～4m | 通用身份跟踪、复杂绕障、道路关系推理 |

2026-10-15 的真实任务“观察确认红车，然后在车尾后方8米、上方2米有效跟随10秒”一次通过两个阶段，无重做：累计有效跟随11.458秒，13次真实Jev请求全部成功，Qwen三次执行请求加一次总结。独立真值在有效跟随区间得到水平间距中位数8.062m、上方2.148m，但横向绝对偏差中位数仍为1.489m。

该轮证明指定街区和目标下链路可运行，不证明多轮稳定性或精确车尾中心线跟随。[验证条件与真值筛选方式](Validation.md#qwen-3秒仿真窗口执行一致性验证2026-10-15)保留了全过程，后文“关键问题”列出当前边界。

## 2. 流程与职责

```text
用户发布 task
    ↓
Qwen 规划 → 校验 version=2 计划
    ↓
当前 stage：RGBD感知 → DINO确认/筛选 → 跟踪与局部几何
                           ↓
                   Jev 行为与阶段判断
                           ↓
                  确定性约束 → PX4
    ↓
阶段结果报告＋最新RGB＋完整Qwen文字历史
    ↓
Qwen：accept / redo / modify_stage / modify_plan / abort
    ↓
完成或失败 → 停止运动、Hold → 一次只读总结
```

| 模块 | 职责 |
| --- | --- |
| Qwen | 生成阶段目标、分配每阶段Jev额度与时长、验收、修改或主动终止 |
| Jev | 根据当前阶段、跟踪和几何事实选择允许行为，报告running/done/failed及原因 |
| 任务运行器 | 管理版本、attempt、预算、墙钟deadline、调用线程、证据和终结 |
| 飞行执行器 | 独占PX4连接，维护Offboard心跳，校验观测与决策，执行速度反馈 |
| 灯箱 | 只读展示文件快照；不持有飞行接口，不调用模型，不启动任务 |

模型线程没有飞行接口。只有与当前 `plan_revision`、`stage_id`、`attempt` 匹配且新鲜的Jev响应可授权动作。硬故障不能由Qwen覆盖。

## 3. 感知与执行

RGB与深度先配对采集，按标定映射检测框；目标位置是可见表面估计，不是车体中心。DINO候选经过置信度下限0.35、car/vehicle/box类别门槛和IoU≥0.5重复框抑制，保留拒绝原因。每次检测重新核对与当前红色RGBD区域的重叠，不无限沿用首次身份确认。

`too_far`、`mixed_depth`、无目标、陈旧观测与错误均保留为事实。有语义候选不等于已有可执行跟踪；无可靠跟踪不平移。粗体素保留clear/blocked/unknown，当前街区对前方未测到阻挡的unknown使用显式限速策略，不把unknown改写成clear。

执行速度上限水平1.2m/s、垂直0.5m/s；Jev约每2秒请求一次，控制心跳约50Hz。主循环300ms未更新时发送零速度。飞行范围限制为距接管点水平65m内、本地NED Z在-6～-1m；遥测陈旧、Offboard丢失、解锁状态或估计异常均终结任务。当前仅控制本机Stage 5、PX4 instance5/system ID6，MAVLink本地监听14545，飞控发送14585；全局锁 `/tmp/uav-stage5-follow.lock` 防止争用。

Jev原因包括observing、approaching、following、achieved、tracking_lost、blocked。正在接近、误差大或有效跟随时间为0不能单独作为失败。执行器校验：

- failed/tracking_lost需要连续8秒无可用跟踪；failed/blocked需要实测阻挡。
- 缺少对应失败事实时保留原始判断、停止运动授权，向Jev反馈并等待新判断，不直接结束阶段。
- done需要已有达标时长；observe需要可用跟踪。未满足时拦截，不自动接受。
- 连续8秒无可用跟踪、15秒无匹配且新鲜的决策，或阶段timeout/额度耗尽，结束当前stage并提交Qwen。

`enabled_follow_s` 包含接近目标的时间；`valid_follow_s` 只累计估计水平目标点误差≤1m、垂直误差≤0.5m的有效许可时段。报告给出全程、末段、最新误差，仍需独立真值验证。

## 4. 计划、验收与进度

计划使用 `version=2` 和有序 `stages`。每个阶段有 `id`、`goal`、`skill`、`dino_text`、完成/失败标准、`allowed_skills`、`allocation`；跟随阶段另含水平距离、上方距离、`duration_s`。

技能、距离、高度、正数额度与时长均校验。goal/完成标准中明确的数字秒数必须与duration_s一致；原始任务仅有一个明确跟随时长且计划有一个跟随阶段时，也校验两者一致。修改阶段/计划继续校验，矛盾时交Qwen修复，不静默改成默认值。这只是明确数字的检查，不是完整自然语言理解。

所有阶段结果，包括failed、budget_exhausted、timeout和执行器错误，都提交Qwen：

| action | 必要参数 | 作用 |
| --- | --- | --- |
| `accept` | 无 | 接受当前结果并推进；最后一个stage接受后任务completed |
| `redo` | 新allocation | 同要求从当前现场重做，继承已有进度，不退还消耗 |
| `modify_stage` | 完整stage、保留id | 修改当前stage，保留后续计划 |
| `modify_plan` | 非空stages后缀 | 替换当前及后续阶段，已接受前缀不可覆盖 |
| `abort` | 非空assessment | 结束为failed/qwen_aborted，并总结无法继续的原因 |

每次修改产生新revision；schema version与revision不同。每次执行有独立attempt。进度键包含阶段目标和配置、排除allocation：仅改额度继承进度，改目标/距离/时长等重新统计；不同stage id不共享累计时间。旧定义、报告与接受记录完整保留。

Qwen仍可接受失败报告；运行器不替它决定阶段效果。因此completed代表所有当前阶段被Qwen接受，不天然等于原始任务已经客观达标。

## 5. Qwen实际看到什么

每轮新增内容是当前任务上下文、当前阶段/计划概要、最新阶段结果报告、预算与执行成本建议，以及 **最新一张RGB**。

结果报告保留状态、原因、Jev最终判断、实际allocation与消耗、执行时长、累计观察/跟随时间、误差指标和结束时跟踪状态。不提交逐次Jev历史、实时DINO/深度/体素JSON、检测框明细、概率数组或PC截图路径。`tracking_at_end` 是阶段结束时的结果，不能当作当前现场。

保留本次任务Qwen此前每轮完整文字输入与原始输出，不做摘要或裁剪；每条历史输入只存当轮内容，不递归复制此前history。历史图片只在本地保存，不重复作为当前画面发送。已返回但JSON/协议校验失败的文字输出也保留，下一次附校验错误。

当前板端HTTP只支持单轮user，客户端将带role的文字历史放在该user JSON的 `history` 中；这不是服务端原生多轮会话。没有启用KV cache。模型看到的是RGB与执行反馈，不包含Gazebo目标真值。

## 6. Qwen等待期间持续运行仿真

当前 mission 不创建仿真暂停控制器。规划、验收、总结、重试和 plan-only 均不自动暂停 Gazebo；无人机等待时保持悬停，车辆与仿真时钟持续运行。模型提示词和 execution_guidance 明确告知等待期间目标可能离开视野，不把阶段结束的观测当作返回时的当前事实。

云端 Qwen 默认关闭思考并直连；短请求测试通过不代表连续运动中的完整飞行通过，仍需实际任务验收。历史3秒暂停策略的证据仅适用于其原配置。旧暂停辅助模块和隔离测试保留供历史诊断，当前入口不启用。

## 7. 预算、时间与结束状态

| 账本 | 定义 |
| --- | --- |
| task Qwen budget | 默认10次；规划、验收、非法结果修复和重试均计数 |
| stage allocation.budget | Qwen分配的本次stage Jev请求上限；失败请求也计数 |
| task timeout | 默认300秒单调墙钟，涵盖连接准备、规划、执行和验收；重做、暂停不延长 |
| stage allocation.timeout | 本次stage墙钟时长，包含模式切换、感知等待和重试 |
| 最终总结 | 预算外额外最多1次，最长30秒，不重试，不能发动作或修改计划 |

每个阶段开始前保留验收调用机会；阶段Jev额度耗尽时等待最后一个在途结果，再报告结果或budget_exhausted。task级累计Jev消耗用于记账，不另设一套Qwen额度。DINO不计入模型调用额度。

执行成本建议依据2秒Jev间隔、速度限制、接近时间与剩余达标时长估算。建议不使用真值、不自动覆盖Qwen分配。原地reacquire没有搜索能力，目标已丢失时单纯增加budget不能恢复目标。

结束时先零速、Hold，再做一次只读总结；失败则生成本地事实摘要。迟到结果不能触发动作或修改已结束任务。Hold不是降落，用户可按操作文档显式降落。

## 8. 灯箱、证据与代码入口

灯箱顶部显示Qwen当前工作、最近决定、额度与token；阶段卡片来自真实计划；感知区区分实时RGB、DINO送检快照与配对深度；引擎灯区分请求中、决策有效、跟踪可用和控制活动。决策建议与实际执行、约束否决分开显示。失败不等于idle，灯灭也不代表服务掉线。

默认自动跟随本工作树最新启动的mission，包含自定义输出目录；`--run`固定查看历史任务。切换按run_id清除旧图，状态与图像不跨任务混用。状态约0.5秒写入/0.7秒轮询，图片约1秒生成/1.2秒轮询；是监控界面，不是飞行实时控制界面。工作树索引只含路径，不含凭据；升级前默认临时任务有兼容发现逻辑。

## 9. 当前仍存在的关键问题

| 优先级 | 问题与证据 | 当前处理与剩余工作 |
| --- | --- | --- |
| P0：任务正确性 | Qwen可能误读失败原因、增加无效额度；先前真实运行把jev_failed说成“额度耗尽”。允许接受失败报告、修改后续目标，也可能让completed偏离原始任务 | 已保留真实原因、增加abort、检查明确数字时长和Jev判断证据；尚无覆盖任意任务语义的最终目标一致性验证。必须结合报告和真值，不以completed替代验收 |
| P0：真实世界适用性 | 连续仿真中模型等待期间目标继续运动，可能离开视野 | 当前等待时悬停；连续跟踪、等待期间可持续执行的控制策略与延迟观测处理尚未实现或验收 |
| P1：感知与恢复 | 只确认当前红车/红方块，依赖颜色和理想RGBD；高分DINO候选仍可能误检，无通用身份、遮挡恢复和主动搜索 | 已筛选候选并显示原因，保留too_far/mixed_depth；需要稳定目标身份、明确歧义状态与可验证搜索技能 |
| P1：几何精度 | 成功轮次真值水平8.062m、上方2.148m，但横向偏差1.489m；低估计误差不代表精确车尾中心线跟随 | 跟随位置基于可见表面和估计运动方向；仍需量化方向/外参/表面偏差，在相同赛道上做独立真值评测 |
| P1：通行能力 | 粗单帧体素、有限前向视野，unknown下的限速策略只在当前街区验证；未实现绕障技能 | 已知阻挡会否决动作；不能将此demo描述为通用避障、自由空间搜索或复杂目标跟随 |
| P1：模型时延与历史增长 | 板端约25 token/s，完整计划生成可达约18秒；保留完整文字历史后prefill逐轮增长，没有KV cache | 精简每轮新增报告，只附一张最新RGB；目前按用户选择暂缓时延优化。后续需固定请求回放，分别测输出协议、缓存和推理后端 |
| P1：超时隔离 | 主线程可以丢弃迟到结果，但Python请求线程及服务端推理不能保证立即取消；客户端history/计时仍由请求对象更新 | 迟到结果无飞行权限；还需按request ID隔离history与metrics，并验证超时后服务busy、总结失败及恢复行为 |
| P2：验证范围 | 有指定场景单次成功与多次失败记录，缺固定初态下多轮成功率、完整一圈、复杂遮挡和板端执行/实机验证 | 当前只标记有证据的链路通过；需固定版本、初态、资源和评价窗口开展重复验证 |
| P2：监控与维护 | 默认选择“最新启动”而非“当前有效执行”任务；失败的并发启动也可能切换灯箱。/tmp证据重启后可能丢失，旧任务兼容发现不具备严格跨工作树归属 | 单执行器锁防止争用；可用--run固定查看。任务列表、执行优先选择、证据持久化、完整浏览器视觉回归尚未完成 |

历史版本或外部操作可能留下暂停状态，需按操作文档手动恢复。当前可执行性校验只覆盖已注册技能和明确数值，不保证模型理解了完整自然语言任务。

## 10. 如何验证后续修改

在PC仓库根目录先做Python语法检查，再运行：

```bash
.venv/bin/python -m unittest discover -s stage5/tests -q
node --check stage5/webui/app.js
```

单元测试不连接设备或付费模型；`tests/integration_agent.py` 使用真实DINO与PX4、模拟Qwen/Jev，会移动无人机，运行前必须满足 [Hands-on](Hands-on.md) 的现场条件。真实模型、暂停/恢复、网络故障、灯箱与飞控链路需分别验证，不能把纯测试当作课程验收。

本次整理不重新调用模型或执行飞行；真实运行证据仍以上述Validation条目为准。
